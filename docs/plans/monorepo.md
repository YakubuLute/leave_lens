# Plan: Monorepo restructure

**Status:** done. Merged in PR #2 on 2026-10-04, with App and Backend CI green.
**Branch:** `chore/monorepo` (from `development` at `c5e6734`)

## 1. Goal

Turn the repo into a monorepo that holds the Flutter app, the FastAPI backend and, later, the ML pipeline. Each part gets its own folder, tooling and rules, plus one shared contract for the `Diagnosis` JSON that the backend returns and the app reads.

**Definition of done:**
- The Flutter app lives in `app/`, with git history kept for every file.
- From `app/`, `flutter analyze`, `flutter test` and `flutter build web` all pass.
- `backend/` is a working FastAPI skeleton with a health endpoint. Lint, type checks and tests all pass.
- `contracts/` holds the `Diagnosis` JSON Schema and example fixtures. The backend tests validate against them.
- CLAUDE.md is split into a repo-wide file plus one per part, and every doc path is updated.
- CI runs the app checks and the backend checks separately, each only when its own folder or the contract changes.

**Out of scope:**
- The real `/v1/diagnose` endpoint and the Claude integration (Phase 4).
- `ml/` (Phase 2).
- Dockerfiles and deployment, because the hosting decision is still open (PLAN §5).

## 3. Changes

### 3.1 Move the Flutter app (commit 1: moves only)
- `git mv` these into `app/`: `lib`, `test`, `assets`, `android`, `ios`, `web`, `pubspec.yaml`, `pubspec.lock`, `analysis_options.yaml` and `.metadata`.
- **Split `.gitignore`.** Flutter and Android patterns move to `app/.gitignore`. Their root-anchored patterns, like `/build/`, then apply relative to `app/`. The root file keeps the OS and editor patterns and adds Python ones: `.venv/`, `__pycache__/`, `.pytest_cache/`, `.ruff_cache/`, `.env`.
- **Local only, not tracked:**
  - Move `.idea/` and `leaf_lense.iml` into `app/`, so Android Studio opens `app/` as the project.
  - Delete the root `.dart_tool/` and `build/`, which are regenerated by `flutter pub get`.
- No content changes in this commit, so git recognises every file as a rename and `git log --follow` keeps working.

### 3.2 Split CLAUDE.md and update the docs (commit 2)
- **Root `CLAUDE.md`:**
  - Product context and a map of the monorepo.
  - §1 "Plan before you implement", unchanged.
  - Contract rules (§3.3).
  - Git rules, and per-part verification commands.
- **`app/CLAUDE.md`:**
  - Today's §2 design system, §3 architecture and §4 Dart practices.
  - Flutter commands, run from `app/`.
  - Also fixes a stale file tree in §2: it lists `leaf_theme_extension.dart`, which doesn't exist. The real files are `leaf_context.dart`, `leaf_component_themes.dart` and so on.
- **`backend/CLAUDE.md`** (Python rules):
  - Layering: `api → domain ← services`. Route handlers stay thin.
  - Typed everything: `pyright` in strict mode.
  - `ruff` for lint and formatting, `pytest` with `httpx` for tests.
  - Settings only from the environment. Never commit secrets: only `.env.example` is tracked.
- Claude Code loads a subfolder's `CLAUDE.md` when it works on files there, so each part gets focused rules without repeating them.
- **Docs paths:**
  - `README.md`: new structure, and getting-started steps for each part.
  - `docs/PLAN.md` §2: `lib/` → `app/lib/`, and so on.
  - `docs/plans/design-system.md`: test paths, and the CLAUDE.md link now points to `app/CLAUDE.md`.

### 3.3 Shared contract (commit 3)
- **`contracts/diagnosis.schema.json`** encodes PLAN §3:
  - `status`, `crop`, `disease`, `pathogen`, `confidence` (0–1), `severity`, `source`, `symptoms`, `treatment` (`immediate`, `organic`, `chemical`, `prevention`) and `disclaimer`.
  - Required fields, enums and value ranges.
  - Status rules: `healthy` and `not_a_leaf` results have `disease: null`; `diseased` requires a disease name.
- **`contracts/fixtures/*.json`:** one valid example per status.
- **Change rule** (written in root CLAUDE.md and `contracts/README.md`):
  - A contract change updates the schema, the fixtures, and both sides' models in the **same PR**.
  - Breaking changes need a version bump in the API path (`/v1` → `/v2`), because old app versions stay installed on phones.
- **Who checks the contract:**
  - **Backend, now:** a test validates every fixture against the schema, and checks that it parses into the Pydantic `Diagnosis` model.
  - **App, later:** the Dart `Diagnosis` model doesn't exist yet (Phase 1). When it's created, its tests must parse the same fixtures. This is noted in `app/CLAUDE.md`.

### 3.4 Backend skeleton (commit 4)
- **Tooling:**
  - `uv` (0.12) with Python **3.14**, which is already installed here.
  - Runtime dependencies: `fastapi`, `uvicorn[standard]` and `pydantic-settings`.
  - Dev dependencies: `pytest`, `httpx`, `ruff`, `pyright` and `jsonschema`.
- **The app:**
  - A `create_app()` factory, so tests build fresh apps.
  - `GET /health` returns `{"status": "ok", "version": …}`.
  - `Settings` reads `ANTHROPIC_API_KEY` but doesn't require it yet. `.env.example` lists it, empty.
- **`domain/diagnosis.py`:** Pydantic models matching the schema, which `/v1/diagnose` will return in Phase 4.
- **Tests:** the health endpoint, plus the contract test from §3.3.
- **`backend/README.md`:** how to install, run (`uv run uvicorn …`), lint, type-check and test.

### 3.5 CI (commit 5)
- **`app.yml`:**
  - Runs on push and PR when `app/**` or `contracts/**` changes.
  - Uses `subosito/flutter-action` pinned to Flutter 3.47.5.
  - Steps: `pub get`, `dart format --set-exit-if-changed`, `analyze` and `test`, all in `app/`.
- **`backend.yml`:**
  - Runs on push and PR when `backend/**` or `contracts/**` changes.
  - Uses `astral-sh/setup-uv`.
  - Steps: `uv sync`, `ruff check`, `ruff format --check`, `pyright` and `pytest`, all in `backend/`.
- These are the first checks the repo has had. PRs will start showing status.

## 5. Risks

| Risk | Mitigation |
|---|---|
| The IDE loses the project after the move | Move `.idea/` and the `.iml` file with it, then open `app/` in Android Studio. A fresh import also works. |
| Lost git history | Do the moves alone in commit 1 with `git mv` and no edits, so git detects pure renames |
| Open PR #1 conflicts with the move | This branch is cut from `development`. Merge or rebase onto whichever base #1 lands in before merging (see open question 2). |
| Python 3.14 wheels missing for a future dependency (for example, TensorFlow in `ml/`) | Only the backend pins 3.14. `ml/` will pin its own version in Phase 2. |
